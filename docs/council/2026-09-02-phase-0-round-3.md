## Validated outcomes

- No keyboard hook is authorized by G1–G7. Any future research requires a new post-G7 owner decision, ADR, threat review, and gate.
- WPF Shell COM work has bounded UI waits, queues, cache fallback, and circuit-breaking without claiming that an in-flight COM call can be cancelled.
- The G1a campaign contains exactly 1,000 activation cases with explicit command/state/concurrency counts; ACK, process, window, placement, and latency semantics are reproducible.
- Simple hotkey/CLI invocation uses resident foreground→pointer→primary placement. Only G1b's strict integrated form supplies source/edge/validated physical anchor context.
- Full-trust MSIX and the fixed unpackaged launcher are both rehearsed; ADR-006 selects at least one stable route that must pass. WiX is only a later packaging implementation if the unpackaged route wins.
- Elevated-parent and elevated-client behavior, named-object ACLs, peer token/session/integrity checks, same-user threat limits, and evidence privacy are explicit.
- The visual token/state table, layout DIPs, minimal search, UIA tree, Narrator journey, display/text scale, locale, contrast, reduced-motion, and touch protocols are canonical and measurable.
- Phase 1 omits inert Power/Session and native-Start footer controls. `Ctrl+Esc` remains the independent native fallback.
- Ember Fusion is a provisional feasibility treatment; G2 still requires a controlled Ember Fusion versus Ember Classic comparison and dated owner selection.

## Decision boundary

This PASS validates the **quality and consistency of the planning packet**. It does not authorize Phase 1 code, declare G0 passed, prove G1a/G1b, or approve a final design.

Next required action: the owner must ratify all eight choices in [the G0 charter](../decisions/GATE_G0_CHARTER.md). If the recommended open-source path is selected, commit the chosen `LICENSE` before implementation code.
